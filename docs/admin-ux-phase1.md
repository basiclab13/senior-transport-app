# 관리자 UI·UX 1차 개선

## 첫 화면과 조작 흐름

관리자 로그인 후 **송영 현황**이 기본으로 열린다. 공통 날짜 선택기에 실제 선택된 날짜·요일·오전/오후를 표시하고, 이용자 수·담당 직원 수·해결할 문제 수를 세 항목으로 요약한다. 화면을 ‘오늘’로 고정하지 않아 기존 09:30/19:00 한국 시간 자동 선택과 수동 선택 유지 정책이 그대로 동작한다.

1. **먼저 해결해 주세요**에서 결근 코스 → 배정 누락·중복·정원 문제 → 방문 시간 문제 순으로 확인한다. 처음에는 최대 세 항목만 표시하고 나머지는 펼쳐 본다.
2. 문제 항목을 누르면 해당 직원·코스의 기존 편집 화면으로 이동한다. 미배정 이용자는 기본 코스를 통해 담당 직원과 연결하고, 방문 시간 문제는 해당 코스로 이동한다. 특정 코스와 연결할 수 없는 전체 문제는 기존 전체 현황으로 안내한다.
3. **직원·이용자 이름 검색**으로 직원별 일정 목록을 좁힌다. 이용자가 다른 코스로 옮겨졌다면 실제 변경 중인 담당 직원을 표시한다. 결석·제외·미배정 이용자도 기본 코스 담당자를 통해 찾을 수 있다.
4. 직원을 선택하면 기존 편집 화면으로 이동한다. PC에서는 직원 목록과 상세가 나란히, 모바일에서는 상세가 별도로 표시된다. **전체 현황/송영 현황**으로 돌아와도 변경 중인 일정은 유지된다.
5. AI 제안은 하단의 보조 작업으로 배치한다. 모바일에서는 툴팁·접근성 이름이 있는 AI 아이콘으로 제공하고, PC에서는 **AI 일정 제안** 버튼을 제공한다. 변경한 코스가 있을 때만 기존 방문 시간 조정 버튼이 나타난다.
6. 마지막에 **변경 내용 확인 후 확정 → 최종 일정 확정**으로 공유한다. AI 적용·방문 시간 조정·최종 일정 확정은 분리되어 있다.

현황은 현재 선택한 날짜·시간대의 **변경 중인 일정**을 기준으로 한다. 확정되지 않았으면 직원에게 아직 공유되지 않았음을 표시한다. 기존 공유 일정에 결근 코스가 남아 있는 경우 경고를 유지한다.

## 숫자와 경고의 의미

- 이용자 수: 해당 시간대 기본 코스의 중복 없는 이용자 수. 배정·결석·제외·미배정 수를 함께 표시한다.
- 담당 직원 수: 현재 코스에 배정된 직원의 중복 없는 수. 실제 출근자 수가 아니다.
- 문제 수: 기존 `confirmationErrors`에서 동일 문구를 묶은 화면의 문제 항목 수. 새로운 확정 기준이나 최적화 점수가 아니다.
- 방문 시간 미입력은 기존처럼 참고 안내다. B-2 시간 확인 미완료와 시간 충돌은 기존처럼 확정을 차단한다. 다른 차단 문제가 있는 상태에서 단순 미입력 안내가 ‘확정 가능’이라고 오해되지 않도록 문구를 구분한다.
- 일정·결근 조회 실패나 로딩 상태에는 정상적인 현황 수치나 ‘문제 없음’을 표시하지 않는다. 기존 조회/재시도 화면과 확정 차단을 유지한다.

직원 목록은 자연 정렬과 필요한 행만 만드는 스크롤 목록을 사용한다. 80명 전체 이용자의 방문 순서를 첫 화면에 길게 펼치지 않고 직원·코스·차량·인원/정원만 표시한다. 방문 순서와 개별 조작은 기존 상세 화면에서 확인한다.

## 주요 용어

| 기존 | 변경 |
|---|---|
| 관리자 화면 | 송영 현황 |
| 직원 화면 | 내 송영 일정 |
| 미확정 변경 포함 | 변경 중인 일정 |
| 재배정 필요 | 다른 직원 배정 필요 |
| 코스 전체 재배정 | 코스 넘기기 |
| 결근 코스 전체 재배정 | 대신 담당할 직원 선택 |
| 확정본 vN 대비 변경사항 | 공유된 일정에서 N항목이 바뀝니다 |
| 전체 직원 변경 검토·확정 | 변경 내용 확인 후 확정 |
| 전체 검증 통과 | 확정 전 확인 완료 |

직원 **결근**, 이용자 **결석**, **일정 확정**의 의미는 유지한다. 사진 등록을 실제 출근·도착 인증으로 바꾸지 않는다. 직원 화면은 제목·짧은 안내 이외의 방문 일정·사진 등록 구조를 유지했다.

## 변경 범위

- `lib/widgets/admin_transport_dashboard.dart`: 현황 요약·우선순위 문제·직원/이용자 검색·직원 목록. 읽어온 기존 컨트롤러 데이터만 사용한다.
- `lib/screens/admin_schedule_view.dart`: 기본 현황/기존 편집 전환, 문제와 검색 결과의 상세 이동, 모바일 편집 도구 한 줄 배치.
- `lib/screens/schedule_screen.dart`: 쉬운 제목·안내, AI 하단 배치, 확정 상태·버튼 표현. 기존 요청·검토·확정 로직은 유지한다.
- `lib/utils/schedule_wording.dart`, `lib/widgets/admin_assignment_overview.dart`, `lib/widgets/course_reassignment_dialog.dart`, `lib/widgets/schedule_change_review.dart`: 주요 용어와 변경 요약 문구 통일.
- `test/admin_dashboard_test.dart`: 신규 현황 테스트 8개와 선택적 로컬 화면 캡처.
- `test/support/fixtures.dart` 및 기존 관련 위젯 테스트: 편집 회귀 테스트가 새 홈에서 **직원별 일정**으로 명시적으로 진입하도록 보완. 기존 검증 시나리오는 유지한다.

Firestore 스키마, Functions, Rules, 인증·역할 코드, 일정 컨트롤러의 업무 규칙·동시 수정 방지·확정 처리에는 이번 작업의 변경이 없다. 별도 컬렉션, 서버 조회, 서비스, 의존성을 추가하지 않았다. 기존 미커밋 작업도 보존했다.

## 검증과 한계

- `flutter analyze`: 문제 없음.
- `flutter test`: 199개 통과(기존 191개 + 현황 8개).
- Auth/Firestore/Functions Emulator 회귀 테스트: 110개 통과. 기존 시연 환경을 건드리지 않도록 별도 포트 9198/8190/5102와 demo namespace에서 실행했다.
- `flutter build web --debug --dart-define=USE_FIREBASE_EMULATORS=true --no-pub`: 성공. 실제 Firebase에 연결하지 않는 Web 결과물로 브라우저 컴파일을 확인했다.
- 새 UI는 직원 20명·이용자 80명 가상 catalog로 기본 현황, 실제 재배정 후 이용자 검색, 결근·미배정·방문 시간 문제 우선순위와 상세 이동, 편집 유지, 조회 실패, 수동 날짜 유지·19시 복귀 정책을 검증했다.
- PC 1440×1000, 모바일 320×844·390×844의 위젯 레이아웃과 검색·스크롤·상세 왕복을 검증했다. 기존 320×568 편집·결근·재배정 테스트도 유지했다.
- 로컬 화면 이미지: `.local-tools/dashboard/pc-overview.png`, `pc-problems.png`, `mobile-320.png`, `mobile-390.png`. Flutter 위젯을 캡처한 이미지이며 실제 모바일 브라우저·실기기 시험을 대신하지 않는다.
- 실제 센터 직원의 ‘10초 이해’ 사용자 테스트, 동시 접속 성능 측정은 수행하지 않았다. 첫 화면에서 목적·선택 일정·핵심 수치·다음 행동이 보이는지 시연 전에 확인하는 것이 좋다.
- 기존 담당 직원의 인계 완료 상태 표현 문제는 [별도 개선 항목](known-issues.md)을 유지한다. 일정 문서 부재만으로 인계 완료를 추정하지 않는다.

로그: `.local-tools/dashboard-flutter-tests.log`, `.local-tools/dashboard-new-tests.log`, `.local-tools/dashboard-emulator-tests.log`, `.local-tools/dashboard-web-build.log`. 실제 Firebase 데이터 변경·배포·외부 Gemini 호출은 수행하지 않았다.

시연은 기존 Emulator 환경에서 `flutter run -d chrome --dart-define=USE_FIREBASE_EMULATORS=true`로 실행한다. 가상 계정·catalog·일정이 이미 준비되어 있다면 재등록하거나 삭제하지 않는다. 관리자 로그인 후 현황에서 문제 또는 직원을 선택해 기존 편집과 별도 일정 확정 흐름을 확인한다.
