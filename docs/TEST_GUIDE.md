# 앱 테스트 안내

코드를 설치하거나 수정하지 않아도 배포된 앱을 사용해 보고 의견을 보낼 수 있습니다. 앱 계정과 GitHub 계정은 별개입니다. 비밀번호는 안내서·Issues·단체 채팅에 적지 마세요.

## 1. 시작 전 확인

1. 담당자에게 현재 앱 주소, 배포 시점, 관리자 또는 직원 테스트 계정을 개인적으로 받습니다.
2. 문서에 안내된 주소는 [송영도우미 웹 앱](https://senior-transport-app.web.app)입니다. 현재 공개 상태와 기능 활성화 여부는 담당자에게 확인합니다.
3. **기본은 조회만** 합니다. 이 앱은 실제 Firebase에 연결되므로 가상 데이터여도 변경 내용이 팀 전체에 공유되고 비용이 발생할 수 있습니다.
4. 결근·결석 등록, 일정 확정, AI 요청, 사진 등록은 담당자가 허용한 계정·날짜·범위에서만 합니다. 허용 범위를 모르면 실행하지 않습니다.
5. 전화번호·실제 주소·얼굴·차량 번호 등 개인정보가 있는 사진은 사용하지 않습니다. 흰 종이나 담당자가 제공한 샘플을 씁니다.

로컬에서 자유롭게 연습하려면 [Emulator 설치 안내](TEAM_GUIDE.md)를 따릅니다. 운영 앱과 로컬 앱의 계정은 서로 사용할 수 없습니다. 별도 권한 안내가 나오면 우회하지 않습니다.

## 2. 공통 확인

- 로그인 성공·실패 안내를 이해할 수 있는가?
- 선택한 날짜와 오전·오후가 명확한가? 직접 고른 날짜가 작업 중 바뀌지 않는가?
- **현재 일정** 버튼으로 돌아갈 수 있는가?
- 휴대폰에서 글자와 버튼이 잘리지 않는가? PC에서도 직원 목록을 비교하기 쉬운가?
- 로그아웃 후 다른 사람의 일정·사진이 남아 보이지 않는가?

처음 선택되는 일정은 한국 시간 기준 00:00~09:29 오늘 오전, 09:30~18:59 오늘 오후, 19:00~23:59 내일 오전입니다. 경계를 시험하려고 기기 시각을 바꾸지 마세요. 자동 테스트로 확인할 수 있습니다.

## 3. 관리자 확인 항목

먼저 조회만으로 확인합니다.

- 송영 현황에서 이용자 수, 담당 직원 수, 처리할 문제를 파악할 수 있는가?
- 직원 이름·어르신 이름 검색 후 해당 일정으로 이동할 수 있는가?
- 직원의 담당 코스·차량·방문 순서를 확인할 수 있는가?
- 오전에는 직접 입력한 약속 시간, 오후에는 방문 순서가 중심으로 보이는가?
- 결근·대체 직원 필요 상태와 단순 확인 사항을 구별할 수 있는가?
- 사진 기록의 등록·미등록·조회 실패가 구별되고 등록 시각을 알 수 있는가?

담당자가 허용한 경우에만 아래 변경 흐름을 확인합니다.

1. 지정한 날짜·시간대의 기존 내용을 기록합니다.
2. 방문 순서 변경, 결석·복귀, 어르신 이동 중 허용된 작업을 수행합니다.
3. 결근 등록과 코스 인계를 확인합니다. 예비 직원의 근무 가능 여부와 정원을 확인합니다.
4. 변경 확인 창의 날짜·오전/오후와 변경 내역을 읽습니다.
5. **일정 확정은 별도 승인받은 경우에만** 누릅니다. 직원 계정에서 공유 내용을 확인합니다.

AI 기능은 활성화되어 있고 담당자가 실호출을 허용한 때만 요청합니다. 한 번 요청한 뒤 성공·실패를 기록하고 자동·반복 재요청하지 않습니다. 변경이 없다는 답도 정상 결과일 수 있습니다. 추천 적용과 최종 일정 확정은 별개입니다.

## 4. 직원 확인 항목

- 본인 일정만 보이고 다른 직원의 일정·사진으로 이동할 수 없는가?
- 담당 코스·차량·이용자 수를 바로 알 수 있는가?
- 방문 순서, 어르신 이름·방문 위치가 읽기 쉬운가?
- 오전 약속 시간이 없는 경우 미입력 안내를 이해할 수 있는가?
- 일정 없음·결근 상태에서 확정되지 않은 인계 완료를 임의로 표시하지 않는가?
- 업무 시작·종료 사진의 다음 등록 버튼과 등록 상태를 찾기 쉬운가?

사진 등록은 담당자가 허용한 **한국 시간 오늘의 본인 확정 일정**에서만 시험합니다. 19시 이후에는 처음에 내일이 선택될 수 있으므로 날짜를 확인합니다. 샘플 사진을 선택하고 확인 후 등록합니다. 등록 시각·완료 상태를 확인하고, 관리자가 같은 기록을 조회하는지 확인합니다. 파일이나 기록을 직접 삭제해서 되돌리지 않습니다.

## 5. 결과 남기기

각 항목을 `통과`, `실패`, `미실시(권한·설정 필요)` 중 하나로 기록합니다. AI·사진 기능이 아직 배포되지 않았거나 비활성화된 경우에는 먼저 담당자에게 확인합니다. 로컬 최신 화면과 배포된 화면이 다를 수 있습니다.

결과에는 확인 날짜와 시각(한국 시간), 관리자/직원, 선택한 일정 날짜·오전/오후, PC/휴대폰과 브라우저를 적습니다. 계정 비밀번호나 UID는 적지 않습니다. 담당자가 정한 표시용 계정 이름으로 구분하세요.

## 6. GitHub에 오류 또는 개선 의견 보내기

1. GitHub에 로그인하고 [프로젝트 저장소](https://github.com/baek-jaekwang/senior-transport-app)를 엽니다.
2. **Issues**에서 비슷한 제목을 먼저 검색합니다. 같은 문제면 기존 글에 결과를 추가합니다.
3. 새 문제라면 **New issue**를 누릅니다.
4. **오류 제보** 또는 **개선 제안** 양식을 선택하고 항목을 작성합니다.
5. 민감정보가 없는지 확인한 뒤 **Submit new issue**를 누릅니다.

Issues가 없거나 양식이 보이지 않으면 담당자에게 요청하세요. 저장소의 Issues 사용 설정과 기본 브랜치에 반영된 양식이 필요합니다. GitHub 웹 화면은 한국어·영어 설정에 따라 버튼 이름이 다를 수 있습니다.

오류는 다음처럼 **같은 결과를 다시 볼 수 있는 순서**로 적습니다.

```text
제목: [오류] 휴대폰에서 직원 검색 버튼이 잘려 보임
환경: 배포된 앱 / 관리자 / Chrome / 화면 너비 390px
선택한 일정: 확인한 날짜와 오전 또는 오후
1. 관리자 로그인 후 송영 현황을 연다.
2. 직원 이름 검색창에 이름 일부를 입력한다.
기대: 검색 결과와 이동 버튼이 모두 보인다.
실제: 이동 버튼 오른쪽이 잘려 누를 수 없다.
```

오류 코드를 안다면 안전한 코드만 적습니다. 전체 Console, 네트워크 요청 헤더, 로그인 토큰, 설정 파일을 복사하지 마세요. 내부 식별자 대신 어느 화면에서 어떤 행동을 했는지 설명하면 됩니다.

## 7. 스크린샷 첨부

1. Windows는 `Win+Shift+S`, 휴대폰은 기기의 화면 캡처 기능을 사용합니다.
2. 비밀번호·계정 이메일·UID·토큰·개인 알림·주소창의 민감한 값이 없는지 확인하고 잘라냅니다.
3. Issues의 설명 또는 스크린샷 입력란에 이미지를 끌어 놓거나 붙여 넣습니다. 업로드 완료를 기다립니다.
4. 오류가 난 부분과 클릭하려던 버튼을 설명합니다. 실제 사람의 개인정보가 있는 이미지는 첨부하지 않습니다.

의도하지 않은 운영 변경을 했다면 추가 조작·재시도·삭제를 멈추고 담당자에게 개인적으로 알립니다. 발생 시각과 변경 행동을 전달하고 복구는 담당자가 진행하도록 합니다.

참고: [GitHub 공식 Issue 작성 안내](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue).
