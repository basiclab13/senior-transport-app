# 관리자 시연 화면 단순화

## 화면 흐름

1. `AI 일정 제안` → 바뀌는 직원/이용자/방문 순서와 예상 이동 거리 확인.
2. `이 일정 사용하기` → AI 제안을 현재 편집 중인 일정에 반영. 직원에게 전달하거나 확정하지 않는다.
3. 자동으로 열리는 `방문 시간 한 번에 맞추기`에서 바뀐 코스를 함께 확인한다. 현재 시간 중 가장 이른 값을 첫 방문 시간으로, B-1의 기본 5분을 방문 사이 간격으로 제안한다. 코스 운행 시작 시간보다 앞서지 않게 제안한다. 시간이 없으면 운행 시작 시간을 쓰며, 둘 다 없으면 사용자가 첫 방문 시간을 입력해야 한다. 예상 운행 종료 시간을 자동으로 늘리거나 계산 실패를 숨기지 않는다.
4. `이 시간으로 적용` → 직접 입력한 시간이 바뀌는 경우에만 `직접 입력한 방문 시간도 바꿀까요?`에서 이전/변경 시간을 확인한다. `확인하고 시간 바꾸기`를 선택해야 적용된다. 처음 입력 방법이 알려지지 않은 과거 시간도 직접 입력으로 취급한다.
5. `전체 직원 변경 검토·확정` → 변경사항 확인 → `최종 일정 확정`. 이 단계에서만 기존 서버 호출로 확정한다.

시간을 나중에 맞추려면 `나중에 하기`를 선택한다. AI가 바꾼 일정은 현재 화면에 남지만 방문 시간 확인 전에는 확정할 수 없다. 상단 `변경된 방문 시간 맞추기`로 다시 시작할 수 있다. AI 외에 수동으로 바꾼 코스도 같은 날짜·시간대의 확인 대상에 포함한다. 기존 직원별 시간 맞추기와 기존 시간 그대로 쓰기 기능도 유지한다.

## 쉬운 표현과 간결한 표시

화면에서 "초안", "수동 시각 보호", "출처", "계산 미리보기", "시각 역전·중복" 대신 "현재 일정", "직접 입력한 시간", "바뀌는 시간 확인", "방문 순서에 맞게 시간을 다시 맞춰 주세요"를 사용한다. 내부 모델·서버 필드·판단 기준의 명칭을 바꾸는 작업은 아니다.

AI 검토에는 변경 전후 일정, 아직 방문 시간을 바꾸지 않았다는 안내, 예상 거리 비교를 우선 표시한다. 추천 이유는 펼쳐 볼 수 있으며 같은 원인의 시간 경고를 길게 나열하지 않는다. 시간 조정 화면에는 바뀌는 시간 수와 직접 입력한 시간 수를 표시하고, 자세한 이전/변경 값은 펼쳐 보거나 최종 수동 시간 확인에서 확인한다. 화면 문구를 검증하는 기존 테스트도 새 표현으로 갱신했으며 기존 검증·권한 테스트는 삭제하지 않는다.

시간 순서가 맞지 않으면 시간 맞추기를 안내하고, 운행 구간을 벗어나면 첫 방문 시간을 앞당기거나 간격을 줄이도록 안내한다. 운행 시작/종료 정보가 잘못됐다면 기존 직원별 화면에서 먼저 수정하도록 안내한다. 직원·차량·이용자 중복은 어느 배정을 고쳐야 하는지 쉬운 말로 표시한다. 내부 오류 코드나 시간 입력 출처 값은 화면에 노출하지 않는다.

## 유지한 안전장치

- B-1 `previewVisitTimes`와 고정 간격 계산을 그대로 재사용한다. 위치 기반 거리에서 방문 시간을 자동 추정하는 새 기능은 추가하지 않는다.
- 확인용 계산은 일정을 변경하지 않는다. 모든 코스 계산 결과를 검사한 후 `_update` 한 번으로 함께 적용하고 B-2 확인 상태를 해제한다. 일부 코스만 적용하지 않는다.
- 직접 입력/과거 시간의 값이 실제로 달라지면 명시 확인이 필수다. 바뀌지 않은 시간의 기존 출처도 유지하며, 출처가 없던 값도 불필요하게 출처 필드를 추가하지 않는다. 바뀐 계산값은 기존 `fixedInterval` 출처를 사용한다.
- 일정 참조, catalog, 결근 리비전, 화면 전환 세대와 확인 대상 코스가 같아야 적용한다. 순서/인원/날짜/시간대/결근 등이 바뀐 오래된 계산 결과는 적용하지 못한다.
- 빈 코스는 시간을 만들어내지 않고 변경할 시간이 없음을 보여준 뒤 확인한다. 잘못된 간격, 자정 초과, 운행 구간/시간 순서 문제는 모두 그대로 차단한다.
- AI 적용, 시간 적용, 최종 서버 확정은 별도다. 기존 Authentication·역할·결근·정원·중복·서버 버전·트랜잭션·중복 요청 방지·Security Rules는 변경하지 않는다.

## 변경 파일

- `lib/services/schedule_controller.dart`: 불변 일괄 확인 결과, 일괄 계산/명시 확인/원자적 적용/오래된 결과 차단.
- `lib/widgets/visit_time_adjustment_dialog.dart`: 기존 계산을 여러 코스에 재사용하는 단일 시간 확인 동선.
- `lib/screens/schedule_screen.dart`: AI 선택 후 시간 조정 연결과 다시 시작 버튼, 쉬운 확정/오류 표현.
- `lib/screens/admin_schedule_view.dart`, `lib/widgets/bulk_visit_time_dialog.dart`, `lib/models/visit_time_review.dart`: 기존 직원별 시간 기능과 확인 표시를 쉬운 말로 변경.
- `lib/widgets/ai_schedule_suggestion_dialog.dart`, `schedule_change_review.dart`, `admin_assignment_overview.dart`: 간결한 검토·안내 표시.
- `lib/utils/schedule_wording.dart`: 화면용 해결 안내. 내부 검증 결과는 유지.
- 기존 테스트/브라우저 시연 도구의 문구 검증 갱신, `test/visit_time_batch_test.dart` 추가.

## 검증

`flutter analyze` 오류 없음, Flutter 전체 테스트 182개와 관련 서버 계산/검증 Node 테스트 38개가 통과했다. Emulator 전용 debug Web 빌드도 성공했다. 화면 동선은 고정 추천 응답과 메모리 저장소로 검증했다. 새 테스트 10개는 여러 코스의 단일 적용, 직접 입력한 시간 변경 거부/확인, 변경 없는 과거 출처 보존, 날짜/시간대·결근·순서 변경에 따른 차단, 운행 구간·간격·자정 오류, 빈 코스, 직원 권한 차단, AI 선택부터 별도 최종 확정까지와 작은 화면의 나중에 하기/재시작을 포함한다.

로그는 Git 제외 `.local-tools/simple-admin-flutter-tests.log`, `.local-tools/simple-admin-node-tests.log`, `.local-tools/simple-admin-web-build.log`에 있다. 이번 변경에는 서버 함수/Rules/Firestore 저장 형식 변경이 없어 실제 Emulator 통합 테스트를 새로 실행하지 않았으며, 실행 중인 Emulator를 중지하거나 데이터를 변경하지 않았다. 실제 Firebase 배포·데이터 변경과 Gemini API 호출도 수행하지 않았다.
