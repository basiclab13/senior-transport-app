# 직원 화면 UI·UX 개선

## 화면 흐름

직원 첫 화면은 공통 날짜·요일·오전/오후 선택기 아래에 본인 이름, 담당 코스·이용자 수·차량·예상 운행 시간을 간결하게 표시한다. 이어서 업무 사진 등록, 방문 순서가 나온다. PC에서는 날짜 선택기와 본문을 최대 720px 너비로 맞춘다.

사진 등록은 기존 `AttendanceScreen`의 등록 흐름을 첫 화면 안에 포함하는 방식으로 재사용했다. 기존 직원별 `staffSchedules`와 본인 `staffId`를 그대로 사용하며, 사진 repository·Firestore 저장·트랜잭션·Rules·Functions는 변경하지 않았다.

| 본인 코스의 사진 상태 | 첫 화면 동작 |
|---|---|
| 시작 미등록 | **업무 시작 사진 등록** 하나만 강조 |
| 시작 등록 완료 | 시작 등록 시각과 **업무 종료 사진 등록** |
| 시작·종료 등록 완료 | 두 등록 시각과 완료 안내, 등록 버튼 없음 |
| 사진 조회 중/실패 | 안내 표시, 확인 전 등록 차단 |
| 코스 없음/결근 | 사진 등록 버튼 없음, 기존 기록은 펼쳐서 조회 가능 |

첫 화면의 버튼 → 사진 선택 → 기존 사진 확인 대화상자 → 명시적 등록 확인 순서다. 별도 사진 페이지로 이동하지 않는다. 사진들은 **등록한 사진 보기**를 펼치면 같은 화면에서 확인한다. 과거 다른 코스의 시작 사진만 존재하면 현재 코스의 종료 사진을 등록할 수 없다.

등록 시각은 기존 서버 시각을 한국 시간으로 표시한다. 일정 날짜와 등록 날짜가 다르면 날짜도 표시하여 당일 등록으로 오해하지 않게 한다. 촬영·도착·실제 근무 시각으로 표시하지 않는다. 기존 시연용 사진 안내와 명시 확인을 유지한다.

## 방문 일정과 상태 안내

- 방문 순번, 이용자 이름, 예상 시각, 방문 주소는 접지 않고 표시한다.
- 특이사항은 **특이사항 보기** 항목을 눌러 펼친다. 내용이 없는 경우 빈 펼치기 버튼을 제공하지 않는다.
- “예상 방문 시간은 실제 운행 시각과 다를 수 있습니다”로 안내를 줄였다. 직원 화면의 버전 번호·내부 확정 이력 상태와 반복되는 긴 설명은 기본 화면에서 제거했다.
- 확인된 본인 결근이 있으면 “선택한 오전/오후는 결근으로 등록되어 있습니다. 담당 일정은 관리자에게 확인해 주세요”를 표시한다. 기존 배정 코스를 정상 운행 목록처럼 표시하지 않는다.
- 확정 문서가 없으면 아직 확정된 일정이 없음을, 확정 문서에 본인 코스가 없으면 배정 코스가 없음을 안내한다. 문서 부재만으로 인계 완료라고 판단하지 않는다. [기존 인계 상태 개선 항목](known-issues.md)은 유지한다.
- 한국 시간 09:30/19:00 자동 선택, 수동 선택 유지, **현재 일정** 복귀는 기존 공통 로직 그대로다. 사진 상태는 직원·날짜·시간대·코스별로 분리하고 선택 변경 시 구독/화면 상태를 새로 만든다.
- 사진 확인 중 일정·결근이 바뀌면 기존 오래된 등록 차단을 유지한다. 사진 확인 대화상자는 현재 인증 세션의 Navigator 안에서 열려 로그아웃·역할 변경 시 이전 화면에 남지 않도록 한다.

사진 등록은 기존처럼 `USE_FIREBASE_EMULATORS=true`, `demo-senior-transport` 환경에서만 활성화된다. 직원이 타 직원의 일정·사진을 조회하도록 권한을 열지 않았다. 관리자 사진 조회 화면도 기존 방식으로 유지한다.

## 변경 파일

| 파일 | 내용 |
|---|---|
| `lib/screens/staff_schedule_view.dart` | 본인 코스 요약·쉬운 빈 상태/결근 안내·사진 패널·접이식 특이사항 연결 |
| `lib/screens/attendance_screen.dart` | 기존 사진 확인·등록 흐름의 embedded 표시, 한 개의 주 버튼, 같은 화면의 사진 펼치기 |
| `lib/widgets/route_timeline.dart` | 직원용 특이사항 접기 옵션. 관리자 기본 동작 유지 |
| `lib/screens/schedule_screen.dart` | 직원의 중복 결근 안내 제거와 PC 본문 너비 정리 |
| `test/staff_ux_test.dart` | 신규 직원 UX 테스트 10개 및 선택적 화면 캡처 |
| 기존 `staff_schedule`, `auth`, `staff_absence`, `widget`, `operations_scale` 테스트 | 사진 페이지 이동 대신 첫 화면 통합과 새 안내 문구로 회귀 시나리오 유지 |

기존 미커밋 관리자·AI·사진 기능 변경사항은 보존했다. 신규 Firebase 서비스, 필드, 패키지를 추가하지 않았다.

## 검증

- `flutter analyze`: 문제 없음.
- Flutter 전체 테스트: 209개 통과(기존 199개 + 직원 UX 10개).
- Auth/Firestore/Functions Emulator 전체 회귀: 110개 통과. 실제 Firebase를 사용하지 않고 별도 포트 9198/8190/5102의 demo namespace에서 실행했다. 기존 시연 Emulator 데이터는 삭제하지 않았다.
- Emulator 전용 debug Web 빌드도 성공했다. 마지막 PC 너비 조정 후 정적 분석과 직원 UX 테스트 10개·화면 캡처를 다시 확인했다.
- 320×568, 390×844, PC 1280×900에서 스크롤 없이 코스·차량·이용자 수·시작 사진 버튼이 보이고 클릭 가능한지 검사했다.
- 첫 화면에서 시작 → 종료 → 완료 전환, 사진 펼치기, 등록 실패·날짜/시간대 변경 중 등록 차단, 다른 코스의 사진 분리, 특이사항 접기·펼치기, 결근/일정 없음 안내를 검증했다.
- 실제 서버 권한은 Emulator 회귀의 직원 본인 접근, 타 직원 접근 거부, 결근·인계 후 등록 차단, 중복 기록 덮어쓰기 차단 테스트로 재확인했다.

화면 이미지: `.local-tools/staff-ux/staff-320.png`, `staff-390.png`, `staff-1280.png`. Flutter 위젯 캡처와 크기 변경 검증이며 실기기 카메라·모바일 브라우저 조작 시험을 대신하지 않는다. 사진 선택은 자동 테스트에서 가상 사진 선택기로 대체했다. 시연 전에 실제 Chrome 또는 스마트폰의 파일/카메라 선택은 수동 확인한다.

로그: `.local-tools/staff-ux-flutter-tests.log`, `.local-tools/staff-ux-new-tests.log`, `.local-tools/staff-ux-emulator-tests.log`, `.local-tools/staff-ux-web-build.log`.

기존 Emulator를 실행한 상태에서 `flutter run -d chrome --dart-define=USE_FIREBASE_EMULATORS=true`로 시연한다. 직원 계정으로 로그인해 본인의 확정 날짜·시간대를 선택하고 첫 화면의 시작/종료 사진 버튼을 누른다. 실제 이용자 개인정보가 없는 시연용 사진만 사용한다. 실제 Firebase 데이터 변경과 배포는 수행하지 않았다.
