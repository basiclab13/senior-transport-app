# 관리자 코스 상세 간소화 — 1단계

## 변경 화면

코스 상단에는 이용자 수/정원, **담당 직원**, **담당 차량**을 읽기 전용으로 표시한다. **담당 직원·차량 변경**을 누르면 기존 드롭다운이 열리고, **변경 닫기**로 접을 수 있다. 편집 영역을 열거나 닫는 동작만으로 일정 데이터가 바뀌지 않는다.

직원·차량 선택은 기존 `c.assign`을 그대로 호출한다. 담당 직원을 바꿔도 기존처럼 차량을 유지한다. 기본 차량 자동 배정, 직원–기본 차량 연결 필드나 새 정책은 이번 단계에 추가하지 않았다.

코스의 중심 정보는 **방문 순서 · 예상 방문 시각**이다. 항상 보이던 운행 시간 편집과 기본 방문 순서 참고 정보는 아래쪽 **추가 설정**에 접었다. 이용자 추가·재배정과 방문 시간 맞추기도 그대로 사용할 수 있다.

**추가 설정 → 예상 운행 …**을 누르면 기존 예상 출발·종료 시각 수정 창이 열린다. 숨기는 것은 UI이며 `startMinute`, `endMinute`, 방문 시각·입력 방식, 계산·검증 데이터는 삭제하거나 초기화하지 않는다.

## 오류 해결 동선

- 정원 초과: 코스에 **정원 초과 · 차량 변경하기**를 표시하고 선택란을 바로 연다.
- 직원 근무 불가 또는 직원/차량 중복: **직원·차량 배정 확인하기**에서 같은 선택란을 연다.
- 운행 구간 오류 또는 방문 시각이 운행 범위와 충돌: **운행 시간 범위 확인·수정**에서 기존 운행 시간 수정 창을 바로 연다. 추가 설정을 먼저 찾을 필요가 없다.
- 방문 순서·시각 문제는 기존 방문 시간 계산과 B-2 확인 흐름을 사용한다.

오류 진입점은 해결을 돕는 UI다. 기존 Flutter 검증·Functions 검증·전체 일정 확정 조건을 대체하거나 완화하지 않는다. 잘못된 배정은 경고와 기존 확정 차단을 유지한다. 결근 등록, 코스 전체 인계, AI 적용, 시간 계산·직접 입력 시각 보호, 직원별 조회·사진 기능도 유지한다.

편집 펼침 상태는 날짜·오전/오후·코스별로 구분하는 로컬 UI 상태이며 Firestore에 저장하지 않는다. 기존 선택 결과는 해당 날짜·시간대의 변경 중인 일정에만 반영하고 최종 저장은 기존 일정 확정으로 수행한다.

## 이번 변경 파일

- `lib/screens/admin_schedule_view.dart`: 읽기 전용 표시, 명시적 배정 편집, 접힌 추가 설정, 오류별 바로가기. 컨트롤러·저장 함수는 변경하지 않았다.
- `test/admin_dashboard_test.dart`: 신규 7개. PC/모바일 기본 표시, 직접 직원 선택 시 기존 차량 유지, 추가 설정의 운행 시간 편집과 방문 시각 보존, 정원 오류의 선택란 열기·확정 차단, 운행 오류의 직접 수정 창 진입을 검증한다.
- `docs/course-detail-stage1.md`: 화면 동선과 검증 결과.

Firestore 스키마, Functions, Rules, 계정, catalog·기본 코스·기존 확정 일정은 이번 작업에서 변경하지 않았다. 기존 미커밋 작업도 보존했다.
