# 관리자 운영 규모 UI

> 직원 이름 자연 정렬, 재배정 대상 검색/필터 및 기존 확정본 대비 변경 요약을 추가했다. 현재 상세 동작과 검증은 [admin-usability-improvements.md](admin-usability-improvements.md)를 참고한다.

## 분석 및 변경 계획

기존 관리자 화면은 900px 이상에서 직원 목록과 한 직원의 상세를 나란히 표시하고, 작은 화면에서는 목록·상세를 전환한다. 직원 검색·근무/배정 필터가 있지만 전체 배정과 이용자 이름으로 담당자를 찾는 기능이 없고, 방문 항목마다 모든 편집 버튼이 노출되어 목록이 길었다.

`ScheduleController.catalog`와 선택 날짜·시간대의 `draft`에 전체 현황에 필요한 직원·코스·차량·이용자가 이미 있다. 컨트롤러의 편집 명령과 검증, 저장소, Auth, confirmSchedule, Security Rules는 유지한다. 새 서버 컬렉션이나 검색용 개인정보 사본을 만들지 않는다.

구현 순서: 전체 현황/이용자 검색 → 기존 상세로 이동 → 방문 항목 접기 → 재배정 대상 정보 → 가상 데이터와 Emulator 회귀 검증.

## 구현

- 상단 `전체 배정 현황`에서 직원별 코스·차량·현재 인원/정원과 방문 순서를 압축 행으로 표시한다. 날짜·오전/오후와 전체 직원/코스/배정/결석/제외/미배정 수를 표시한다. 검색에 의해 전체 집계 수가 줄어들지 않는다.
- 현황은 선택 날짜·시간대의 현재 초안을 사용한다. 미확정 변경 포함, 기본 배정 초안, 확정 일정을 구분한다. 조회 창 자체는 저장·확정하지 않는다. 검증 오류가 있으면 오류 건수를 알리고 기존 전체 검증에서 확인하도록 안내한다.
- `직원별 현황`에서 직원 또는 배정 이용자 이름으로 행을 검색한다. `이용자 찾기`에서는 이용자 이름과 현재 담당 직원 이름으로 찾을 수 있다. 결과에는 현재 담당 직원·코스·방문 위치가 표시된다. 중복 배정은 해당 배정들을 각각 표시하며 결석/제외는 현재 배정처럼 표시하지 않고 기본 코스 담당으로 이동한다.
- 결과를 선택하면 기존 직원 필터를 초기화하고 해당 직원/코스로 이동하며, 배정된 이용자의 방문 항목을 펼친다. 작은 화면에서도 같은 흐름으로 상세로 이동하고 직원 목록으로 돌아올 수 있다.
- 방문 항목은 순번·이름·위치·예상 시각을 표시하고, 선택해 펼치면 주의사항과 시각 수정·순서 변경·재배정·결석·제외를 제공한다. 직원 화면의 세로 타임라인은 기존 표시를 유지한다.
- 재배정 목록에는 대상 직원과 코스, 직원의 현재 총 배정 인원, 차량, 코스 인원/정원, 이동 후 인원을 표시한다. 정원 초과와 근무 불가를 알린다. 초안에서 잘못된 배정을 만들 수는 있으나 기존 전체 검증과 서버 검증을 통과하기 전에는 확정할 수 없다.
- 목록은 필요한 행을 생성하는 스크롤 목록이다. 작은 화면에서는 직원 검색·필터도 함께 스크롤되어 높이 초과를 방지한다. PC 현황은 열 형태, 좁은 현황은 줄바꿈 형태다.

## 변경 파일과 검증

`admin_schedule_view.dart`: 현황 진입·직원 상세 이동·재배정 정보·직원 목록 스크롤.
`admin_assignment_overview.dart`: 읽기 전용 전체 현황·이용자 검색.
`route_timeline.dart`: 관리자 전용 접기 옵션(직원 화면의 기본값은 기존 동작).
`admin_overview_test.dart`: 직원 20명·이용자 80명·차량 20대·오전/오후 각각 20코스의 가상 fixture와 UI 흐름. 이 데이터는 테스트에만 있으며 실제 기본 catalog나 앱 데이터에 섞이지 않는다.
기존 관리자 시각/결석·40명/79명·확정 테스트는 방문 항목을 먼저 펼치는 사용자 흐름으로 유지한다.

실제 Firestore와 Authentication 데이터·계정·규칙·Functions는 수정하거나 배포하지 않는다. 검색은 현재 조회된 catalog/초안을 사용하며 서버 전체 이용자 검색이나 개인정보 마스터 생성 기능은 아니다. 미배정 직원에게 이용자를 직접 옮기려면 먼저 기존 코스를 배정해야 한다는 제약과 관리자 검토 후 확정 방식은 유지한다.

2026-11-12 로컬 검증 결과: flutter analyze 문제 없음, flutter test 54개 모두 통과(운영 규모 UI 테스트 6개 포함), Auth/Firestore/Functions Emulator 테스트 33개 모두 통과, `flutter build web --dart-define=USE_FIREBASE_EMULATORS=true` 성공. UI 테스트는 주입한 가상 저장소로 검색·상세 이동·수정·검증을 확인하고 Emulator 테스트는 기존 실제 SDK/Rules/서버 연동의 회귀를 확인한다. 브라우저에서 UI부터 Emulator 저장까지 연결하는 자동 E2E 테스트나 실제 운영 데이터 검증을 수행했다는 의미는 아니다.
