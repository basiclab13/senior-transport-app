# 관리자 UI 최종 정리

2026-11-14 로컬 UI 작업. 기존 디자인과 업무 흐름을 유지하고 화면의 상태 표시·정보 밀도·버튼 위치를 정리했다. Firebase 조회/설정 변경/배포/운영 데이터 변경은 수행하지 않았다.

## 전체 현황

- 기존 이용자/담당 직원/해결할 문제 요약 카드를 유지. 문제 수는 확정 차단 항목만 계산하고 정상 안내의 반복 문구를 제거했다.
- 오류는 **확정 불가**, 예상 시간 미입력은 **확인 필요**로 구분한다. 미입력 목록은 펼쳐 보며 해당 직원/코스로 이동한다. 다른 오류가 있으면 일정 전체가 확정 가능하다고 표시하지 않는다.
- 기준은 기존 confirmationErrors/B-2 재검토 오류/동시 수정 충돌이다. 서버 validation.js도 예상 방문 시각을 입력하지 않은 상태와 양쪽 운행 구간 미입력을 허용하므로 미입력 자체는 차단 사유로 추가하지 않았다.
- 직원 이름 자연 정렬, 검색과 직원 상세 이동을 유지한다. 검색 너비는 최대480px, 안내 영역은 최대760px로 묶었다. PC 표/모바일 카드 구조를 유지하고 모바일은 코스·차량과 이용자 수·상태를 줄로 나눴다.
- 정상/결근·배정 불가/시간 확인 상태는 아이콘과 색을 함께 사용한다.

## 일정 상태와 하단

admin_schedule_status.dart는 표시 전용이며 controller의 dirty tracking이나 publish 조건을 바꾸지 않는다. 확정본이 없으면 미확정 일정, 확정본과 코스·담당자·차량·순서·시각·결석/제외 등 실제 내용이 다를 때 변경사항 있음으로 표시한다. 날짜/시간대 전환·단순 열람·내용이 같은 편집만으로 변경 표시를 만들지 않는다. 확정 후에는 확정된 일정으로 표시한다.

변경 없는 확정 일정은 조용한 상태 표시를 사용한다. 편집을 되돌려 실제 내용이 같아진 경우 기존 일정 확인 대화상자는 보조 TextButton으로 유지한다. 실제 변경·미확정 상태에서는 기존 변경 요약 → 명시적 승인 → 전체 확정 절차를 그대로 제공한다. 동시 수정 충돌은 확정 불가 안내에 포함하며 재조회가 필요하다고 표시한다.

AI 일정 제안은 관리자 상단 보조 버튼으로 이동하고 모바일에서는 tooltip이 있는 아이콘으로 제공한다. 하단은 일정 상태·확인 결과·확정 작업에 집중한다. 하단은 본문 위에 겹치는 overlay가 아니라 Expanded 본문과 별도 영역으로 유지한다. 좁은 화면에서는 상태/확인 아이콘 다음 줄에 확정 버튼을 배치한다.

## 직원 상세와 사진

직원 목록·근무/배정 필터·선택 상세 구조를 유지한다. 직원 정보 및 결근 관리 영역에서 결근 등록·취소를 바로 실행하며 기존 코스 인계 버튼도 유지한다. 방문 순서와 예상 시각의 편집 기능은 바꾸지 않았다.

사진 미등록은 작은 상태 행만 표시하고 빈 이미지 공간을 만들지 않는다. 등록 여부와 한국 등록 시각은 바로 보인다. 사진은 눌렀을 때100px 미리보기, 크게 보기에서는300px로 확장한다. 확대·축소·접기/펼치기는 동일한 메모리 이미지를 재사용해 새 요청을 하지 않는다. 직원/날짜/시간대/사용자 변경 시 이전 펼침·확대·이미지 캐시는 초기화한다. 다른 직원의 늦은 응답이 새 선택을 대체하지 않는 기존 방어를 유지했다.

getWorkPhotos의 메타데이터/사진 요청 분리와 권한 검증, 직원 사진 등록 화면, 저장 방식은 변경하지 않았다. 미등록/조회 실패/이미지 로딩 실패를 구분한다. 실패를 빈 기록으로 처리하지 않는다.

## 남은 사용성·배포 확인

- 20명/80명은 전체 직원을 한 화면에 압축하지 않고 스크롤·검색하는 방식이다. 작은 모바일/높이가 낮은 창에서는 상세 일정까지 스크롤이 필요하다.
- 위젯 레이아웃/캡처 검증은 실제 Safari/PWA 촬영·사진 속도 검증을 대신하지 않는다. 스마트폰 실기기와 큰 글자 설정은 배포 전 확인 대상이다.
- 관리자 사진 갱신은 기존과 같이 명시적 새로고침 방식이다. 실시간 push나 새로운 조회 주기는 도입하지 않았다.
- 배포할 때 최신 Web을 기존 AI/사진 활성화 옵션에 맞춰 다시 빌드한다. 이번 UI만을 위해 Functions/Auth/Firestore·Storage Rules를 재배포하거나 운영 포인터·계정을 바꿀 필요가 없다. 사진 서버 기능의 별도 배포·권한 준비 여부는 기존 운영 준비 문서를 따른다.
- 이번에는 서버/규칙/데이터 구조를 바꾸지 않아 Emulator 서버 회귀를 재실행하지 않았다. 기존 Flutter 전체 회귀로 등록·조회·일정·결근·AI UI 흐름을 검증한다.
