# 관리자 직원 상세의 사진 기록

2026-11-14 로컬 UI 변경. 실제 Firebase 조회·설정 변경·배포는 수행하지 않았다.

## 화면 흐름

직원 상세를 열면 선택한 날짜·오전/오후의 업무 시작·종료 기록과 한국 등록 시각이 바로 보인다. PC에서는 나란히, 좁은 화면에서는 세로로 배치한다. 결근 기능은 기존 직원 정보 영역에 유지하고 사진 조회용 이동 버튼은 제거했다.

사진은 각 기록의 **사진 보기**에서 현재 화면 안에 펼쳐진다. 사진 접기 후 다시 열어도 같은 화면에서는 내려받은 이미지를 재사용한다. 등록 이력이 여러 코스에 있으면 코스 이름과 함께 모두 표시한다.

- 서버 조회 성공 + 기록 없음: **미등록**.
- 등록 정보 조회 중: 확인 중 안내. 미등록으로 표시하지 않는다.
- 등록 정보 조회 실패: 미등록 여부를 알 수 없다는 오류와 새로고침 안내. 이전 사진도 성공한 최신 조회처럼 보여주지 않는다.
- 등록은 확인됐지만 사진 요청 실패: 시각은 유지하고 이미지 오류·명시적 재시도 버튼을 표시한다.
- 직원/날짜/시간대/로그인 사용자 변경: 이전 사진 펼침·캐시를 비운다. 이전 선택의 늦은 응답은 현재 결과로 반영하지 않는다.

## 조회 방식과 범위

WorkPhotoRepository에 메타데이터 전용 summaries와 사진 전용 photo를 추가했다. 둘 다 기존 getWorkPhotos Callable을 재사용한다. summaries는 recordId 없이 페이지를 조회하고 사진은 받지 않는다. photo는 recordId를 지정하고 반환된 직원·날짜·시간대·코스·종류·등록 시각이 일치하는지 확인한다.

이미지 캐시는 관리자 패널의 메모리에만 존재한다. 화면 내 접기/펼치기, 부모 재빌드, 같은 기록의 메타데이터 새로고침은 이미지 재요청을 발생시키지 않는다. 이미지 실패 시에는 자동 재시도하지 않고 **사진 다시 불러오기**를 사용한다. 목록을 스크롤해도 패널 상태를 유지한다.

기존 Emulator Blob은 문서 자체에 사진이 들어 있어 메타데이터와 이미지의 전송 분리가 불가능하다. 기존 watch 경로로 서버 확인된 첫 결과를 받아 이미 포함된 바이트를 재사용하며, 별도 사진 요청을 추가하지 않는다. 초기 캐시 확인 중 이벤트는 미등록으로 취급하지 않고 서버 응답을 기다리며, 15초 안에 검증되지 않으면 오류를 표시한다.

직원용 등록/조회 화면과 기존 watch/register 동작, 저장 구조, Functions, Firestore/Storage Rules, 관리자 서버 권한 검증, 일정·결근 로직은 변경하지 않았다. 관리자 패널만 관리자 역할에서 조회를 시작하며, 실제 데이터 접근 권한은 기존 서버가 계속 검증한다.
