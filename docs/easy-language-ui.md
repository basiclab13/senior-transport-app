# 쉬운 표현과 간결한 화면

2026-11-14 로컬 UI 변경. Cloud Functions, Rules, 데이터 구조, 권한 정책, 저장 필드/내부 식별자, Auth 설정 및 실제 Firebase 데이터는 변경하지 않았다. Gemini 호출·실제 사진 업로드·배포도 하지 않았다.

## 주요 문구 비교

| 이전 표시 | 변경 표시/위치 |
|---|---|
| AI 일정 제안 검토 | 추천 일정 확인 |
| 현재 일정과 변경사항이 없습니다 + 비활성 적용 버튼 | 현재 일정 그대로 사용해도 됩니다 + 확인 버튼 하나 |
| 가상 직선거리 비교·추정 이동 거리와 긴 설명 | 기본 화면에서 숨김. 자세히 보기에서 거리 참고값·비교 결과와 한계 확인 |
| 변경 N항목 | 담당 직원 변경 N코스 / 이용자 이동 N명 / 방문 순서 변경 N코스 |

| users/active/role/boolean 설정 설명 | 계정 설정을 확인해야 합니다. 관리자에게 문의해 주세요. |

| 사진 등록은 Emulator 시연 환경에서 사용 가능 | 사진 등록을 사용할 수 없습니다. 관리자에게 문의해 주세요. |

| 테스트 문맥 지원 서버·별도 옵션 필요 | 지금은 조회·편집만 가능합니다. AI 추천은 사용할 수 없습니다. |

이용자·코스·결근·결석·약속 시간·방문 순서·일정 확정 등 업무 용어는 유지한다. 오류 로그의 진단 코드와 기존 서비스 오류 객체는 그대로이며 화면에 표시하는 메시지만 쉬운 표현으로 바꾼다. 날짜별 미저장 내용 폐기, 권한 부족, 확정 전 직원 공유 안 됨, 개인정보 없는 사진 사용 경고는 유지한다.

## 추천 화면

변경 없음은 날짜/오전·오후, 짧은 안내, 확인 버튼만 표시한다. 고정480px 공간과 거리/추천 근거/사용 불가 적용 버튼을 없앴다. 확인은 false로 닫으며 초안 적용이나 저장을 호출하지 않는다. 요청 이후 일정이 바뀐 경우에는 그대로 사용하라는 안내 대신 다시 추천받도록 안내한다.

변경 있음은 변경 코스 수와 직원 변경·이용자 이동·순서 변경을 먼저 표시한다. 코스별 이전/추천 순서는 펼쳐 확인한다. 직원만 바뀐 코스의 이용자를 다른 코스로 이동한 것처럼 집계하지 않는다. 거리 참고값, 실제 증가/감소 결과, 추천 설명은 기본적으로 접는다. 실제 도로 거리/운행 시간의 절감 효과가 아니라는 한계를 상세 정보에 반드시 함께 표시한다. 개선되지 않은 결과를 개선됐다고 바꾸지 않는다.

적용은 기존 bool 승인 반환과 controller.applyAiSuggestion을 그대로 사용한다. 적용 전까지 초안은 바뀌지 않고, 적용 후에도 일정 확정은 별도다. 오래된 추천 승인 차단·서버 검증·시간 보존·관리자 권한은 변경하지 않는다. 화면 높이는 변경 코스 수에 따라300~480px 범위로 제한하고 내부 목록을 스크롤하므로, 상세 내용을 펼쳐도 하단 버튼은 유지된다.

## 시연 표시와 이름

일반 관리자/직원/로그인 화면의 반복 배너를 제거하고 앱 안내 아이콘으로 모았다. 일반 상단에는 송영 현황/내 송영 일정 제목을 한 번 표시하고, 송영도우미 브랜드는 로그인/앱 안내에 유지한다. 좁은 화면의 로그아웃은 툴팁이 있는 기본 크기 아이콘으로 표시한다.

AI 테스트 전용 화면의 분리·미저장 배너는 유지한다. 미리보기 저장 차단이나 허용 catalog를 변경하지 않는다.

displayName은 이름 앞의 '가상 '만 화면에서 숨긴다. 새로운 실명이나 ID 기반 별명을 만들지 않는다. 원본 catalog의 이름/ID, 계정 연결, manifest/hash 및 스냅샷은 그대로다. 기존 이름을 붙여 넣어 검색해도 접두어를 정리해 찾을 수 있다. 주소/특이사항은 임의로 바꾸지 않는다.

## 검증과 적용 시 확인

최종 분석/전체 테스트/캡처 및 빌드 결과는 아래 완료 기록에 추가한다. 테스트는 로컬 메모리 저장소·고정 AI 응답을 사용한다. 새 Firebase 조회·사진 다운로드를 추가하지 않았으며 기존 사진 캐시/조회 횟수 회귀도 전체 테스트에 포함된다.

- `flutter analyze`: 문제 없음.
- Flutter 전체 **257개 통과**(기존243개 + 신규14개). 로그인·일정 조회/확정·결근·결석·인계·AI 승인·사진 등록/조회·캐시 회귀 포함.
- 320/390/768/1280px: 변경 없음/있음, 짧은 대화상자, 상세 펼치기, 버튼 경계, 앱 안내 표시/닫기, 원본 데이터 유지 검사 통과.
- 화면 집중 테스트 **24개 통과**(14개 새 검사 + 10개 기존 표현/확정 검사). 한글 폰트로 로컬 캡처를 생성하고 320px 변경 없음, 390/1280px 변경 있음 이미지를 직접 확인했다. 큰 빈 공간을 줄였고 상세를 펼친 경우 내부 목록 스크롤을 유지했다.
- 실제 Firebase 연결용 Web release 빌드와 Hosting 파일 검사 통과. AI/Storage 사진 플래그는 기존 운영 빌드 도구 옵션을 사용했다. 로컬 빌드 fingerprint: `facbbe88e8fc9d5e1cbb6a85f0ce8511316e1abd70374a47864942c86801c159`. 배포하지 않았다.
- `git diff --check` 통과(CRLF 안내만 있음). 이번에는 서버 변경이 없어 Emulator/Functions 회귀는 재실행하지 않았다.

로그: `.local-tools/friendly-analyze-verified.log`, `friendly-flutter-verified.log`, `friendly-focused.log`, `friendly-layout-verified.log`, `friendly-web.log`. 캡처는 `.local-tools/friendly-ui/`에 있으며 Git에 넣지 않는다. 초기 실패 로그와 최종 결과는 구분한다.

초기 회귀의 예전 문구/기본 펼침 기대값을 새 표현과 접기 동작에 맞췄다. 추천 영역 높이를 줄이는 과정에서 발견한 상세 펼침의 Flutter intrinsic layout 오류는 높이가 제한된 내부 목록으로 해결하고 전체 테스트를 재실행했다. 이를 해결하기 위해 검증·권한·승인 조건을 완화하지 않았다.

실제 센터 직원 대상 관찰 테스트와 실기기 PWA 카메라 테스트는 이번 범위에서 수행하지 않았다. 운영 반영 전에는 사용자에게 앱 안내 위치·추천 확인·펼치기 기능을 짧게 보여주고 발견하기 쉬운지 확인하는 것이 남아 있다. 이번 변경 자체는 Functions/Rules/데이터 변경이 필요하지 않다. 이전 작업에서 준비한 방문 시간 서버 정책 등의 별도 배포 의존성은 해당 작업 문서를 따른다.

Hosting 반영 시에는 새 Web 빌드/파일 검사를 거친 뒤 별도 승인된 배포 절차를 사용하고, 열린 탭/PWA가 최신 화면을 사용하는지 확인한다. 이번 작업에서는 배포하지 않았다.
